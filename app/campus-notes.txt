//Note: TailwindCSS ----------------
Visibility:
🪄 hidden = gone
👻 invisible = still there but unseen
👀 visible = there and seen


Pseudo variant classes
・hover: → mouse is over
・focus: → element focused
・active: mouse clicked
・(others) visited, focus-within, focus-visible.

Style descendants based on the parent/structure
First: Inyect "group" or "group/{name}" to the parent target. 
・group-hover:*  targets group descendants (deeply or not)
・group-hover/{name}:*  same, but with named groups
・group-has-{*}: Conditional render, but with TailwindCSS.

Style the parent based on descendant
・has-{pseudo}: For example: label.has-checked:*>input.checked:*
・focus-visible:* → when focus is keyboard-triggered
・focus-within:*

Style based on sibling:
First: Inyect "peer" on sibling target.
・peer-invalid, on the other sibling. etc.
・peer-has-{pseudo (like checked)}: style based on a nephew of target.
*Tip: "invisible peer-invalid:visible" for error messages, instead of conditional styling/rendering


first:*, last:*, odd:*, even:*,

INPUTS
required:*, invalid:*, and disabled:*.
checked:*  for the radio type.

peer & focus-within: → Style the parent when a child input (peer) is focused


placeholder-shown: → input is empty and showing placeholder
not-placeholder-shown: → input has value

other goodies:
placeholder, marker, file, selection


disabled: → disabled state

aria-[invalid=true]: → when input has aria-invalid="true"
